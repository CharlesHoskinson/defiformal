# Atomic metatheory transfer author draft

[M6/Sprint14](../openspec/changes/atomic-metatheory-transfer/proposal.md) is a
provisional plan for four capabilities,14 requirements,37 scenarios,25 tasks,
20 fixture families and18 runtime mutations. All implementation/evidence remains
pending. Accepted S10/M3/M4/M5 and an exact API/control refresh must precede the
same-candidate nonauthor GPT-6/native Fable planning gate.

The finite wrapper calls the actual finite dispatcher once per active token and
updates the existing principal/lane settlement table from the actual appended
receipt. The tree wrapper calls the actual tree dispatcher. Their simulation
preserves one label, entry world, ordered policy, schedule, settlement monitor and
outer commit boundary, including first abort position and diagnostic owed state.
Aborted receipts/outputs remain tentative; public state rolls back exactly.

The active-extension theorem is deliberately stronger than M5: all policy lane
cells are protected, added writes avoid them, and added invocations independently
succeed and pass lane-supply checks. New steps therefore create no obligations.
A new mint can violate policy even when it does not touch the vault. Added-peer
refusal remains an explicit foreign abort, never erased by projection. Old abort
positions are normalized using actual restricted token prefixes, not event counts.

Nonempty draw7/return7 examples test real transient owed7/cash3 and final clearance.
Cross-principal repayment retains separate signed residuals; an over-return credit
must be compensated before commit. The successful three-stream extension has12
complete schedules with separately proved new enabledness and independent exact
expected diagnostics/public observations.

Moving transaction boundaries is outside the theorem. One batch containing
transfer7 then refused6 rolls back to10/0/0; two boundaries retain3/7/0. An early
finish after draw7 aborts before the later return. Different schedules can also
select different first failures. These are planned concrete negative companions,
not reports of new execution or changes to the accepted Atomic implementation.

The draft author cannot serve as its nonauthor reviewer. No implementation,
Lean build, mutation run, native invocation, source edit or commit was performed.
GPT-6 stock-harness implementation and native Grok/Fable5.1 medium result reviews
remain future gates; no Foreman. Dynamic capability provenance, general new-lane
interaction, nested boundaries and deployed fidelity remain separate work.
