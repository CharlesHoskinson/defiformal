Uniswap Protocols Overview
Navigate the Uniswap protocol documentation, from the core AMM versions to supporting infrastructure contracts.
Protocols
Uniswap is a suite of onchain protocols. At its core are the automated market maker (AMM) contracts, the pool contracts that hold liquidity and execute swaps. Surrounding them are supporting protocols that handle routing, token approvals, resource locking, smart wallet delegation, and fee distribution.
This page helps you orient within the protocol documentation and find the right starting point for your integration.
AMM Protocols
The AMM is the heart of Uniswap. Each version introduced architectural changes that improved capital efficiency, composability, and gas costs.
Uniswap v4 is the current and recommended version for new integrations.
Uniswap v4
v4 consolidates all pools into a single
PoolManager
contract and introduces
hooks
, external contracts that can customize pool behavior at every stage of its lifecycle (initialization, swaps, liquidity changes, fee logic). It uses
flash accounting
to defer token transfers until the end of a transaction, enabling significant gas savings for multi-step operations.
v4 is the most flexible and gas-efficient version of the protocol. If you are building a new integration, start here.

Supporting Protocols
Beyond the AMM, Uniswap relies on a set of infrastructure contracts that handle routing, approvals, fee distribution, and more. These protocols are used across multiple AMM versions and are important for production integrations.
Universal Router
The Universal Router is an unowned, non-upgradeable contract that composes swaps across Uniswap v2, Uniswap v3, and Uniswap v4 in a single transaction. It uses a command-based encoding system and integrates with Permit2 for signature-controlled token approvals.
If you are executing swaps programmatically, the Universal Router is the recommended entry point.
Universal Router documentation
Permit2
Permit2 unifies signature-based token transfers and time-bound allowances into a single contract. It is used by the Universal Router, the
PositionManager
, and other Uniswap contracts to reduce repeated approval transactions and improve security.
Permit2 documentation
Protocol Fees
Fees
from all Uniswap protocol versions flow through Fee Adapter contracts into a per-chain TokenJar. Releaser contracts define how collected fees are accessed, for example, the Firepit Releaser burns UNI in exchange for collected assets.
Protocol Fees documentation
The Compact
The Compact is an ownerless ERC-6909 contract that enables
resource locks
, tokens that are credibly committed for asynchronous conditions and claimed once those conditions are met. It supports single-chain and multichain flows and is used in cross-chain coordination.
The Compact documentation
Smart wallet (Calibur)
Uniswap smart wallet features are powered by Calibur, a non-upgradeable contract implementation for EIP-7702 delegation. Users delegate to the implementation while keeping their existing EOA address.
Smart Wallet documentation
Security
Uniswap Labs maintains an active bug bounty program on Cantina for eligible vulnerability disclosures.

FAQ
Which Uniswap protocol version should I use for a new integration?
Uniswap v4 is the current and recommended version for new integrations. It consolidates all pools into a single
PoolManager
contract, supports
hooks
that customize pool behavior across the pool lifecycle, and uses
flash accounting
to defer token transfers until the end of a transaction, which reduces gas for multi-step operations.
Use
Uniswap v3
for existing concentrated liquidity integrations and
Uniswap v2
for legacy constant product workflows.
What is the difference between the Uniswap AMM and its supporting protocols?
The AMM contracts are the pool contracts that hold liquidity and execute swaps, versioned as Uniswap v2, v3, and v4. The supporting protocols are infrastructure contracts used across versions:
Universal Router
: composes swaps across v2, v3, and v4 in a single transaction.
Permit2
: signature-based token transfers and time-bound allowances.
Protocol Fees
: Fee Adapter and TokenJar contracts that collect protocol fees.
The Compact
: ERC-6909 resource locks for cross-chain coordination.
Smart wallet (Calibur)
: EIP-7702 delegation for smart wallet features.
Which contract should I use to execute Uniswap swaps programmatically?
The
Universal Router
is the recommended entry point for executing swaps programmatically. It is an unowned, non-upgradeable contract that composes swaps across Uniswap v2, v3, and v4 in a single transaction using command-based encoding, and it integrates with
Permit2
for signature-controlled token approvals.
Are the Uniswap protocol contracts audited?
Yes. The Uniswap v4
core audits
and
periphery audits
are published in their repositories, and Uniswap Labs maintains an active
bug bounty program on Cantina
for eligible vulnerability disclosures.
Where do I find Uniswap contract deployment addresses?
The
unified deployments page
lists Uniswap contract addresses across all protocols and chains. Each protocol section of the docs also has its own deployments page; for example,
Uniswap v4 addresses
are on the v4 deployments page, and the
smart wallet deployments page
lists the Calibur address across supported networks.
