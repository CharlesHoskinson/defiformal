# Lending readiness advisory

READY_FOR_FOCUSED_REFERENCE_MODEL_IMPLEMENTATION, with the operation conventions below made explicit in the first slice. The brief faithfully covers IV.4's repay, accrual, collateral deposit and withdrawal beside borrow. It preserves the existing borrow example and negatives and correctly requires actual kernel execution and evidence before capability-cell updates. No external blocker is established. The task/spec does not condition IV.4 on P27 opening; the design table's P27 association does not override its explicit liquidation-only P27 condition. Missing historical effort/outside reproduction does not block authorized dependency-ready engineering, and remains open evidence.

The next concrete step is to freeze a small state/operation contract and implement one decisive actual effect regression, not dispatch a historical family brief. Choose a debt denomination, nonnegative/positive amount convention and over-repayment policy; distinguish borrower's free collateral from locked custody and bind that custody to the position owner. A distinct holder cell for the same collateral asset can model locking without inventing collateral supply. If separate free/locked receipt assets are chosen instead, their conversion and supply relation need explicit proofs. The current brief permits this implementation choice; it does not yet define it.

Repay must decrease borrower cash, increase pool cash and decrease that borrower's debt together. Debt burn also needs the matching negative debt supply delta and applicable debit/supply authority; zero net scalar change is not per-asset accounting. A debt token is an accounting liability, not spendable cash or a new pool asset. Prove cash/collateral conservation separately from debt-supply reconciliation; do not claim all asset totals remain constant when debt is issued or accrued. Guard or explicitly clamp repayment above outstanding debt, and test the chosen actual behavior along with insufficient cash.

Accrual must add debt and its matching supply change with no cash delta. State whether the increment is simple rate×elapsed time or another explicit rational convention, and reject invalid signs. If caller-supplied elapsed time is accepted, state the replay/reapplication assumption; a time-indexed API needs a last-accrual boundary and a no-double-accrual argument before claiming elapsed-time lifecycle fidelity. This is an internal semantic design decision, not an external dependency. Interest may make a previously healthy position undercollateralized. Include a successful such example; preserve accounting/nonnegativity instead of assuming post-solvency or fabricating an insolvency refusal. Repayment/deposit can remain useful for unhealthy positions and should not accidentally require health restoration unless that restriction is explicitly intended.

Collateral withdrawal must check the post-withdrawal locked collateral, not the free wallet or pre-withdrawal amount, against actual current debt. Borrow checks debt after the requested increase and actual pool cash availability. Positive price, the chosen collateralization factor, oracle unit and observation key must be explicit. Freshness requires observedAt≤now as well as now≤observedAt+maxAge; authenticity is still an assumption. Existing Typed Expr evaluates both operands of Boolean binary operators, so missing/wrong-unit observations can yield evaluation refusals before guard rejection. Freeze exact observable refusal priorities rather than treating every invalid oracle as a generic guard failure. Zero-exposure controls isolate price positivity from the collateral inequality, as the existing acceptance suite demonstrates.

Use actual registered templates, request/context binding, required read/env footprints, write footprints and explicit invoke/debit/changeSupply rights. The framework checks aggregate net effects and does not enforce protocol policy merely because a supply permission exists. Keep the registry restricted to intended operations; do not expose an arbitrary debt-burn path and then claim that the new repay template prevents all debt forgiveness. Fresh/revoked/wrong principal rights, insufficient funds, over-repay, stale/future/missing/wrong-unit oracle, withdrawal health boundary and accrual-induced insolvency are useful actual representative controls. A decisive wrong-effect or omitted-health-guard mutant must execute the changed implementation and show the wrong accepted observation/refusal; proof rejection is separate evidence.

Historical Typed.Examples.borrow uses Alice's collateral cell as declared locked collateral, exact debt denomination and an explicit oracle freshness/positive-price guard. The older untyped Examples.policyDebtBurn and Acceptance.policy_overgrant_debt_burn_post explicitly allow debt to disappear without repayment under the permissive policy. They must remain unchanged; a new restricted reference API does not invalidate them. No deployed source pin is required for the declared reference-model scope. Any later source-fidelity claim needs its own real source gate.

These are concrete design obligations for faithful implementation, not a new approval hold or task completion. The brief is adequate to begin that focused work with explicit conventions; the operation proofs/campaigns/package and independent reviews remain to be done.
