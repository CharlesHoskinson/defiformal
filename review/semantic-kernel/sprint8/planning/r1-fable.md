Why the plan is implementable on the frozen source

- One real advance per token. Interleaving.advance has exactly four outcomes. When the branch failure is none and the static slot is selected, it calls executeStep once and appends exactly one attempt via Machine.refuse or Machine.accept. The appended attempt sits at index equal to the previous attempt count. The one-appended-attempt lemma is a direct case split on advance_sound; no new executor is needed.
- Every token yields an attempt before abort. Admission requires a complete schedule. Complete.left_slot and Complete.right_slot with continueRun_consumed give that the selected slot exists for every token of a prefix with no earlier failure. The out-of-range skip in the executable is therefore unreachable after admission, and the prefix correspondence theorem should take Complete as a premise rather than reasoning about skips.
- Diagnostic machine equals an actual prefix. Because Atomic calls advance on the same config, boundaries, branches and machine, and stops at the first abort, the speculative machine after k tokens is definitionally runPrefix over schedule.take k. The policy-abort case keeps the successful step, so it is runPrefix over take (k+1). Both are genuine Interleaving prefixes, and Reachable, Reachable.attempts, Reachable.store and Reachable.attempt_index apply unchanged.
- Local index and principal. With no failure, Reachable.attempt_index gives nextIndex equal to consumed, so the boundary used by the kernel is boundaries b at the static index. Typed.execute uses that ctx.principal as caller and for authority, and claimedActor must match it. Attribution to the boundary principal is therefore attribution to the authenticated invoker.
- Cash plus obligations. For a successful invoke, StepSound.invoke carries the applied equation, and applyEvaluated_ok_iff gives post balance equals pre balance plus e.effect at every cell. Subtracting the same e.effect at the vault cell from the invoker entry makes cash plus the participant sum invariant in one line. Evaluated.effect already sums repeated deltas. The bridge in Settlement.lean is real but small. The invariant needs two premises the plan already states: participants duplicate-free and every static boundary principal covered.
- Lane supply. Evaluated.supply is per domain and asset, and accountingOK ties it to the party sum of effects. A mint into a nonvault cell of the lane asset gives nonzero supply while the vault cell is untouched, exactly as the scenario claims. A zero net supply pair inside the lane asset passes this policy; that is a stated bound, not a defect.
- Rollback and store. Public noncommit results return the entry world by construction, and Reachable.store shows the speculative store never changes, so store identity holds even on commit.
- Correspondence and macro invariant. Commit implies both branch failures are none on a complete schedule, so runInterleaving returns the same machine, and admit_of_checks rebuilds the Interleaving admission from the Atomic preflight. Reachable.two_invariants and every_prefix_two_invariants supply the noncircular initialized rule for ledger predicates on every speculative prefix, with abort discharged by initialization.
- Counts. I count 16 requirements, 49 scenarios and 40 tasks, and 52 named cases in the existing runner control harness, matching the plan.

Mutant feasibility, given the anchors chosen below

Each of the 18 can be a single needle edit in a DefiKernel.Atomic module that compiles, trips an independent false oracle and keeps the listed positives true.

1. Retain prefix on abort: abort payload uses speculative world. Oracle: middle-failure full-ledger rollback. Positive: immediate failure (no prefix) still equals entry.
2. Continue peer after first failure: drop the inert guard. Oracle: diagnostic attempt count on the immediate-failure fixture, where later peer work is valid. Public world alone cannot detect this, so the fixture must read the diagnostic accessor.
3. Publish aborted outputs and 4. count aborted supply: edit the committed-history and committed-supply accessors (see watchpoint one). Oracle: aborted nonlane mint fixture with zero public supply and empty committed history.
5. Stale entry-world call: pass the entry world into advance. Oracle: live-read fixture, as in Sprint 7.
6. Peer-history leakage and 7. global boundary index: rewrite the machine's own outputs, or the boundaries argument, before the advance call inside Atomic.advance. Oracles: peer-only refusal beside a funded own-history sibling; timed boundaries under a schedule where global position differs from local index.
8. Erase debt without receipt: zero the entry on zero effect. Oracle: draw then no-op then settle expects residual plus seven. Positive: draw and return still commits.
9. Opposite sign: add instead of subtract. Draw and return still commits, so the oracle must be the exact residual value on under-return (plus one expected, minus one observed). Exact residual comparison is required, not just abort kind.
10. Global sum only and 11. collapse principal keys: both trip the cross-principal fixture. Disclose the overlap.
12. Collapse asset or domain keys: cross-asset and cross-domain fixtures.
13. Omit last lane and 14. omit last participant: dropLast in final enumeration. Fixtures need at least two lanes and two participants with the residual only on the last key.
15. Accept lane supply: remove the check. Oracle: nonvault lane mint must abort; the mutant commits because the vault entry is untouched. Positive: authorized nonlane supply commits.
16. Resurrect revoked grants: set every store entry live before advance. Oracle: revoked fixture.
17. and 18. Omit an abort or residual observation field: comparator or projection edit. Oracle: changed-field pairs in the production comparator.

Compile failure, missing observations or a failed positive must stay classified as blocked, which the existing runner already enforces via the single expected error line.

Nonblocking watchpoints

- Committed accessors as production code. Public abort constructors carry no outputs or supply, so mutants three and four have no anchor unless committed history and committed supply are named production functions on the diagnostic result that return empty and zero on abort and are what the public projection uses. Adopt this. It also gives the proved distinction between diagnostic and committed accounting a definitional home.
- Table as a function of actual attempts. Define the obligation table as a fold over the speculative machine's successful attempts, using attempt.branch and attempt.index to read the principal, and prove the Atomic table equals that fold. Then the converse correspondence premises can be stated on the Interleaving machine alone: the attempt-derived table is zero and every successful receipt has zero lane supply. This avoids any circular reference to the Atomic result.
- Mutation module scope. Restrict mutation modules to DefiKernel.Atomic roots. Mutants five, six, seven and sixteen must then be pre-call rewrites inside Atomic.advance, never edits to Interleaving.advance. Strip proof tails only for Atomic modules and retain Interleaving proofs unchanged, so the post-marker runtime check applies to Atomic files only. Keep the Atomic runtime import closure free of proof-only Interleaving modules that use decide with kernel reduction, to keep per-mutant compile time bounded.
- Freeze needles before the first run. The candidate fixes the count and names but cannot fix needle text before source exists. Record the full mutation spec with needles and required-false names at the task 7.6 freeze, before any mutant executes. Any later anchor change after observing a survivor needs a documented reason and refreshed control runs.
- Nonzero intermediate obligation as evidence. The nonempty-settlement scenario is only met if a runtime check reads the diagnostic table after a prefix and asserts the exact nonzero value. Add that check to every transient fixture, not only a final commit or abort outcome.
- Schedule in the comparator. The Sprint 7 comparator deliberately ignores schedule on refused results. The Atomic comparator must include schedule for all three kinds, and the sensitivity fixtures must include a schedule-only change for each kind.
- Fixture construction cost. Cross-principal, cross-domain and two-lane fixtures need new templates, store grants for bob and for the other domain, and funded balances beyond Parallel.Examples. This is ordinary work but is the largest fixture effort in the sprint; start it early in task 4.6 rather than at 6.1.
- Order-sensitive outcome. Under a nonempty single-participant lane both orders of the shared-vault fixtures abort. Use an empty lane set, or two participants, so one order commits and the other aborts.
- Macro invariant instance. The rely-guarantee rule covers ledger predicates only. The task 5.5 instance should be a ledger predicate that holds while obligations are internally nonzero; the cash-plus-obligation law stays a separate Atomic induction and should not be presented as a rely-guarantee invariant.

Exact scope and limits of this audit

I assessed implementability against the frozen Lean definitions, consistency across the planning documents, nonvacuity of the generic proof obligations, and whether each fixture family and each mutant has an independent oracle and a protected positive. I did not check openspec strict validation, hashes, line numbers in coverage.json, Lean compile behavior, runtime timings or reviewer availability. Bounds retained by the plan and confirmed here: exact rational proof-carrying cash, finite binary fixed-capability events, a reference loan and return clearing policy, no general signed ledgers, no Balancer, hook, fee, runtime or deployment fidelity, no liveness, no provenance, no order independence, and no strengthening of the historical Interface or Nary results. Sprint 7 final delivery and a fresh baseline remain prerequisites for any Atomic implementation.
