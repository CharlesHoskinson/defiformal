## Findings and funding gates

**S1 — High strategic priority: source correspondence is the critical missing assurance layer.** The approved design explicitly calls the initial models references rather than ERC-20/ERC-4626/deployed credit models. D still uses trusted registries, invocation contexts, environment values and finite deployment universes (`Typed/Types.lean:5`; `Typed/Transition.lean:32`). Kernel correctness cannot show that those inputs encode an actual contract, authenticated actor or truthful oracle. More executor modes do not close that gap.

Minimal validation: select one pinned implementation and one economically interpretable safety property; bind source revision, initial-state relation, input relation, successful and refused observations, and arithmetic semantics. Run independent differential cases and prove one universal refinement lemma for the supported operation. Include a source mutation that violates the chosen property while the source-model boundary detects the difference. Kill criterion: if a bounded attempt cannot state the relation without assuming the desired postcondition or excluding normal supported behavior, stop generic expansion and revise that adapter/model boundary. This is a sequencing recommendation, not a claim that all deployed behaviors must be formalized first.

**S2 — High claim-boundary priority: net accounting and nonnegative balances are not solvency, allowance consumption, or transaction-order fidelity.** `Typed/Types.lean:32` stores a proof of nonnegativity in every state. `Typed/Transition.lean:162` checks the final aggregate effect before constructing that proof. This is useful defensive semantics, but a theorem projecting the stored witness adds no independent economic fact. The file explicitly excludes intermediate debit order, consumable allowances and replay prevention (lines 5–6). A net-zero debit/credit sequence is not modeled as a sequence of intermediate debits inside one template. Authorized supply changes can preserve accounting while economically diluting holders.

Minimal validation: headline each financial claim with its exact predicate, initialization, environment assumptions and executable boundary. For a loan claim, distinguish book-entry debt/payment consistency from collateral valuation and solvency. Require a negative example with conserved totals and nonnegative balances that nevertheless violates the selected financial property. Kill criterion: a proposed “financial guarantee” that only restates type membership or accounting should be renamed and receive no new economic-coverage credit.

**S3 — Medium: generic preservation can hide all difficulty inside local obligations; require nonvacuous reuse evidence.** `Causal.lean:56` assumes the selected component's actual-success guarantee; its success-update obligation assumes established post-invariants and asks for preservation of the stronger joint invariant. That is a valid inductive rule, not automated discovery of assumptions. The funded witness's `fundedRely` is simply the post-invariant (`FundedCausal.lean:92`), so peer stability alone is easy; the meaningful work is proving the local transitions and joint invariant. No circularity was found in this sample, but future instances can instantiate unhelpful predicates or very strong assumptions.

Minimal validation: every advertised new instance supplies an inhabited initial state, at least one actual successful nontrivial transition, one refusing/violating control, and explicit discharged versus external premises. Measure whether a second source-bound component reuses the first component's contracts without re-proving the complete global execution. Kill criterion: if repeated instances require a full bespoke execution proof with little reuse, simplify the general contract API before adding more layers.

**S4 — Medium: theorem/inventory counts measure audit completeness, not independent financial coverage.** The M3 adjudication records 1,459 imported theorem constants, 1,131 supplemental definitions and 317 unresolved/ambiguous source-owner attributions. It explicitly forbids treating these as independently authored generic/economic claims. `Causal.lean:191` and 196 are useful definitional equalities; `FundedCausal.lean:413` onward contains finite cell inequalities. Neither is an independent financial guarantee. The 310 observations and 16 mutations similarly have different denominators.

Minimal validation: retain the full proof inventory, but use a small assurance matrix as the decision dashboard: property, quantified domain, source relation, discharged premises, refusal behavior, mutation class and acceptance revision. Kill criterion: no milestone receives financial-coverage credit solely from increased theorem, label or harness-control counts.

**S5 — Medium: serialized certificates are a useful boundary improvement, not source verification by themselves.** The certificates worktree's `openspec/changes/serialized-kernel-certificates/design.md` is explicitly unimplemented planning. It correctly proposes decoding into Lean and invoking actual Typed/Composition entrypoints rather than a Python semantic clone. Source maps, observation authenticity and library obligations remain separate trust/obligation classes. A certificate that reproduces kernel execution still does not prove its source map truthful.

Minimal validation: retain universal codec/correspondence targets, recomputation of actual executor results, full refusal observations, and distinct unchecked source/library obligations. Do not broaden the first increment to every executor family. Kill criterion: reject any report that promotes a supplied theorem name, source hash string or claimed judgment to proof without checking the associated binding and obligation.
