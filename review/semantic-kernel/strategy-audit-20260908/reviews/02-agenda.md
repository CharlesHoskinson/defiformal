## Objective and smallest useful next deliverable

The approved design's objective is conditional preservation of financial properties under composition, with distinct ontology, libraries, semantics and adapters. Its first useful increment was three executable reference models with preservation proofs and rejected broken variants. That increment is already behind us. Rebuilding a pilot or declaring the whole migration complete at another reference-only milestone would misread the mandate. See `docs/superpowers/specs/2026-09-06-semantic-kernel-design.md`, Objective, First executable increment and Acceptance; `docs/research/semantic-kernel-progress.md`, Sprints 5–11 and checked integer arithmetic.

The smallest valuable NEXT deliverable should be one reproducible financial workflow tied to an exact available implementation revision, with successful and refused behavior, a genuinely discriminating fault, an explicit observation mapping, and a bounded concrete correspondence result. Reuse accepted arithmetic and composition. Choose the narrowest source-grounded operation for which these obligations can actually be met; concentrated-liquidity single-step arithmetic is a candidate, not a predetermined winner or credit for full tick traversal. A user can then reproduce a claim about an identified financial operation and see what assumptions remain. Neither another generic operator nor an artifact-count increase supplies that benefit alone.

This is an intermediate acceptance boundary, not removal of claims, async, full libraries, adapters or publication from user-authorized scope. AGENTS.md's 2026-09-08 scope and WORKSTATE.objective explicitly retain the entire program.

Recommendation B is sequencing, not a permanent cap or scope cancellation. Keep M4 as the first bounded semantic lane because recovery already exists and unlocks M5. Do not automatically prioritize finishing all Claims over reviewing M4; select Claims next if the financial slice concretely requires liability semantics or its bounded proof closes sooner without displacing acceptance. Existing candidate evidence makes review and triage preferable to restarting either branch.

1. **Recovery gate, before new authorship:** inventory exact latest candidate bytes, actual terminal status, independent verdict, remaining finding and integration prerequisites for each lane. Resolve conflicting current status pointers. Each artifact must be accepted in its exact scope, needs revision, partial, or unavailable; no exit-code-only approvals. Preserve cancelled Claims output. 2. **Acceptance queue gate:** prioritize M4 recovery, the Claims partial-proof disposition, capability foundation, production metadata and historical/honest-gate candidates. Close concrete findings and integrate only independently accepted scopes. Review the Atlas candidate only as a bounded existing closeout. Start another author lane only when a checker is available and this does not displace a candidate ready for delivery. This is a work-in-progress policy, not an invented quota or duration estimate.
3. **M4 nonvacuity experiment:** before broad M4 evidence expansion, exhibit distinct participants with nonempty writes satisfying the actual checker and instantiate recovery with exact success/refusal observations. The r1 self-pair compatibility finding forced empty writes (WORKSTATE.m4_recovery.interim_finding); the r2 proof must remove that defect without weakening the independent semantic target. Failed experiment means revise compatibility/theorem scope, not generate more fixtures.
4. **Financial selection gate:** on already available source evidence, select one operation, pin its executable reference and relevant source closure, state success/refusal observations and explicit environmental assumptions. Validate one positive boundary case and one characteristic arithmetic/failure mutation against an independent oracle before expensive Lean porting or full-loop modeling. For the liquidity candidate, specifically resolve denominator-wrap behavior and prove the proposed directional/fallback fault is observable: WORKSTATE.next_independent_preparation.concentrated_liquidity retains those concrete interim findings. A fault not discriminated by its protected case must be repaired or reclassified.
5. **Certificate decision experiment:** only if serialized verification serves the selected slice, freeze one small input/result contract and demonstrate that a forged supplied judgment is rejected by recomputation while the valid case passes. Specify the exact Lean judgment to which checker success will correspond, including refusal and outstanding assumptions. If that contract cannot be stated without unresolved operators, defer the broad serializer and retain Lean proof artifacts for the slice; do not claim certificate completion.
6. **Slice acceptance gate:** exact source identity, executable positive and refusal comparisons, discriminating mutation with positive control, checked relevant Lean theorem/correspondence, explicit assumptions and independent exact-candidate review. Deliver to semantic-kernel-pivot and verify publication/archive as already authorized. Report measured/proved scope separately; a narrow arithmetic slice does not close full concentrated liquidity, deployment fidelity or all environments.
7. **Expansion decision:** use the accepted slice to choose the next missing financial behavior. Resume M5 only after delivered M4 and actual API refresh; M6 after its explicit prerequisites. Resume broad Claims/async/provenance when their workflow or roadmap gate is the selected next deliverable. Resume full source/corpus completion and publication according to their actual evidence dependencies. Untouched evaluation remains sealed until the kernel and exposure policy are frozen.

## Stop, defer and retain

Stop now: speculative M5/M6 implementation; new presentation features; new broad library ports without source/oracle readiness; reopening accepted packages for numerical proof/test-count growth; launching author work solely because another lane is blocked. Return to these only with a specific accepted input contract, an actual unresolved deliverable and available review capacity.

Defer: full tick traversal, remaining protocol families, wide certificates, new runtime adapters and final scientific visualization until the narrow source-bound experiment and relevant APIs settle. Return when the selected next workflow or proved interface supplies their missing prerequisites. Keep them open in the authorized program.

Retain: all historical models/proofs, negative results, exact reviews, cancelled partials and source identities. “Purge false starts” should remove abandoned routes from current execution pointers and classify their evidence as superseded; it must not erase historical proofs, silently rewrite old claims, delete candidates before preservation, or hide failures. Correct current misleading claims without relabeling old acceptance.

## Conditions that would falsify this recommendation

- If the selected financial slice demonstrably needs M5/M6 and no useful smaller source-bound slice exists, strategy A becomes preferable; document the concrete dependency instead of inferring it from milestone numbering.
- If exact independent reviews and verified deliveries can keep pace with multiple genuinely disjoint lanes without repeated API rebasing or interrupted gates, the proposed concurrency restraint is too conservative. Measure accepted deliverables and unresolved findings, not authored artifacts or stale process IDs.
- If locally available source evidence cannot support any independent executable reference, the proposed immediate fidelity experiment is blocked. Continue bounded M4/Claims proof and source-readiness work; do not fabricate source fidelity or count a reference fixture as deployed correspondence.
- If a smallest slice succeeds only under premises that already assert its financial conclusion, it has failed the user-benefit criterion. Redesign the initialization/discharge experiment before expanding libraries.

The program remains unfinished. The needed change is from many concurrent authored candidates to a controlled sequence of independently accepted results that tests the kernel against financial behavior early.
