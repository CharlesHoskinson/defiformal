WHAT I CHECKED AGAINST THE FROZEN SOURCE

The design's reading of the existing kernel is accurate on every point I could verify. Composition.executeStep does validate the whole catalog first; invocation goes through the complete lookupOperation pair, the registry template at inv.operation, checkAccess, Typed.execute (which consults the registry exactly once, at request.operation), then extractReceipt (registry again at the same operation) and snapshots from the selected interface. Issue goes through Config.authority = registryAuthorityConfig cfg.registry cfg.domainAdmin, whose operationDomain is (registry op).map Template.domain evaluated at Grant.operation; there is indeed no grant.scope field. Revoke reads the capability from the current store and consults domainAdmin of that capability's dynamically read domain. Parallel.observeBranch does retain index/step/receipt/outputs, outputs history, nextIndex and failure and does drop raw event worlds. continueRun is a fold with continueRun_append and continueRun_failed available. Composition.advance is inert on a failed cursor.

The three central M1 theorems are derivable under this code, non-circularly:

- runGroup = continueRun on flatten follows by induction on the three constructors using continueRun_nil, the single-step unfolding, and continueRun_append. No success premise and no initial-cursor restriction are needed. Empty identities, refusal absorption (continueRun_failed) and associativity (List append associativity through the simulation) all follow, at full cursor equality including raw event worlds.
- advance/runGroup preserving CursorEquivalent is sound: the only data CursorEquivalent omits (past raw event before/after worlds) is not read by advance, and pointwise ledger equality plus store equality upgrade to definitional world equality via funext and proof irrelevance, both inside the allowed axiom set (propext, Classical.choice, Quot.sound). So projection adequacy holds: every field advance reads (world, outputs, nextIndex, failure) is observed.
- The universal-input GroupEquivalent and the fill substitution laws go through for the before/after fixed-hole grammar, and the stated negative witness is genuinely load-bearing: two groups sharing an initially refusing first action produce identical failed cursors at the original entry, while a fixed authorized funding prefix exposes the differing suffixes. One-entry equality really is insufficient.

ConfigAgreement is sufficient for exact executeStep equality, and each premise is used where the plan says: registry equality at the supported operation for prepareInvocation/execute/extractReceipt; complete lookupOperation equality (including None, which yields the same .interface .unknownOperation refusal) for the invoke path; registry equality at Grant.operation for operationDomain on issue; all-domain domainAdmin equality for revoke against an arbitrary store. Both-catalogs-valid gives equal startCursor and equal first-check behaviour. Lifting through continueRun, recursive groups, analyzeInvocation/analyzeBranch, Parallel/Interleaving/Atomic admission (checkCompatibility, checkSchedule, checkPolicy are all configuration-free) and Atomic attempt/outstanding/finish is a mechanical consequence, since runAtomic depends on cfg only through admit and executeStep.

REQUIRED CHANGES

1. Comparator locality is ambiguous and can make six planned mutants unimplementable. Design section 2 both says to "reuse existing world/branch equality lemmas where useful" and to keep field comparisons in the new module. Since imported kernel source must stay byte-identical, M09-M14 cannot delegate to Parallel.worldEq or to the derived DecidableEq on BranchObservation/EventObservation. State explicitly that the production Boolean comparator is written in Observation.lean with separable conjuncts for ledger, store, frozen history, nextIndex, failure, and a locally written per-event comparison exposing index/step/receipt/outputs as distinct conjuncts (M13 requires the receipt to be its own site). Reuse of existing equality artifacts is permitted for proofs only.

2. Bind the mutation-fixture cost. The Sprint8 runner strips proof tails only for modules under the scoped prefix and inlines every other local dependency with its proofs intact. Under a Metatheory prefix, the fixture will re-elaborate the entire Typed/Composition/Parallel/Interleaving/Atomic proof corpus once per variant, fifteen times. Require in task 7.5 an explicit per-command timeout, a measured wall-time record, and an import discipline that keeps proof-only modules out of the Audit/Tests closure. Concretely: have Metatheory.Tests/Examples import Atomic.Examples and Parallel.Examples rather than Atomic.Tests or Parallel.ObservationTests, which would drag in Composition.Examples with its maxHeartbeats 2000000 decide +kernel workflow proof. A timeout here fails as blocked (exit 3), so the failure mode is zero semantic detections, not a false pass.

3. Enumerate the runner adaptation points in task 7.1. The frozen check_atomic_mutations.py hardcodes DefiKernel.Atomic in the scoped-module regex, the required audit root, the namespace-closure regex on proof suffixes, and the expected_error string "Atomic runtime comparisons failed: N" on which mutant classification depends; test_atomic_mutation_runner.py additionally hardcodes fixture module names and the same error string in its production-audit assertions. Bind the new audit's exact error text and list these strings in the old/new name map, not just the 65 case names.

4. Specify the M08 source site. The new interpreter does not index the boundary function; Composition.advance does. State the intended single-site form (passing a constant-position boundary at the leaf call) so the mutant is a change in new code and not a forbidden edit to imported kernel bytes.

5. Restate the "identical fixed types P, A and D and the same corresponding instances" clause as a constraint on the theorem's binder shape, not as a field of ConfigAgreement; it is not expressible as a Prop field without heterogeneous equality.

6. Mark premise necessity honestly in the counterexample requirement. Full registry-template equality at supported operations and all-domain admin agreement are deliberately stronger than minimal; the six named negatives establish materiality, not minimality. The "each material agreement premise" wording should say so.

The design already separates M09-M14 from the eight routing detections; the evidence spec should also carry the word synthetic/unreachable so the 14 are never read as 14 financial-execution detections.
- The parser-control provenance count is imprecise: twelve controls in the frozen inventory concern the proof-tail boundary, while the plan says "11 proof-tail parser controls" plus 52 earlier plus 2 production-form. - Counterexample constructibility notes, so implementation does not stall: the changed-registry witness must alter guard/deltas/writes rather than signature or output domain, since validateCatalog checks those; the grant-only operation-domain witness needs an operation with no declaring catalog component, otherwise changing Template.domain invalidates the catalog and collides with the both-valid premise; the changed component-declaration witness must preserve export/import/private-cell validity.

For lean/lake-manifest.json and for all supplied JSON evidence artifacts (author-validation, scenario-planning-map, dependency-baseline-binding, gate-evidence, acceptance, delivery, archive-delivery, log-pointer-fix-binding), the rendered bytes differ from the originals.
