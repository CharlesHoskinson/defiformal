# Exposure audit of the twelve proposed holdouts

**All twelve have prior design exposure in existing repository records. None can be presented as untouched on the evidence inspected here.** This is a conservative exposure assessment, not an evaluation manifest, a certification of contamination completeness, or a selection of replacement cases. No external sources or new prospective cases were retrieved.

The approved migration design says cases already used to design the kernel are development challenges, not untouched holdouts (`docs/superpowers/specs/2026-09-06-semantic-kernel-design.md:56–59`). The twelve-name table in the adopted source plan is not just a list: its rows describe mechanisms, the following paragraphs analyze them, and line394 explicitly uses the group to favor a kernel based on state, effects, interfaces, authority, timing and assumptions. Several cases are then used again to specify concrete future financial libraries. That design use predates the later implemented kernel freezes.

The cited source-plan lines are retained from commit `43c2b1b264f542d3ef741130373115ed1b62b5a6`, committed September6,2026 at14:07:26−06:00, before the first transition-pilot commit. Older original corpus examples are retained from `93ee29dacf2963e6957b16220f31412dda329676`, committed August4,2026 at09:05:40−06:00. These are repository-history dates, not verified original research/publication dates. Exact line-introduction commits, source-file hashes, Git blobs and line hashes are in `assessment.json`.

## Corpus membership and repeated evidence

None of these twelve names/family patterns matches a standalone `original.name` among the72 normalized source records or `identity.label` among the75 normalization candidates. **That does not establish novelty.** The older supplied corpus documents, nested component references, category residue, library examples and actual historical model text are distinct evidence surfaces. UMA appears inside Across/Polymarket and a bundled prediction-market comparison; unversioned Euler appears inside Steakhouse; Kamino appears in prior research/specification of that substrate; Balancer V3 appears in category-level residue despite exclusion from the top-five rows.

Search results include copies in review bundles and graph outputs; those copies are not independent design events. The raw lexical inventory also deliberately retains false-positive candidates for inspection. Excluded examples include constant-velocity UI motion, the academic `maude.lcc.uma.es` domain, zkLink Nexus, generic load balancers and Euler v1 when reasoning specifically about V2. Existing citation tokens/URLs are provenance text, not newly verified financial sources.

## Scope, preservation and artifacts

The deterministic search covered20,047 existing tracked UTF-8 text files selected by `git ls-files`, excluding dependency/build/vendor directories and this new output directory. Symlinks were not followed. `all-name-matches.jsonl` preserves every discovered matched line's path, line, columns, context and hash; `scan-inputs.json` records scope, patterns and every scanned file's byte hash. The graphify source graph was checked for scope orientation, but it excludes research/corpus documentation and cannot certify exposure absence.

`assessment.json` contains12 case judgments and47 selected source-evidence records, including retained path histories and exact line-level Git provenance. History checking follows selected extant paths and their blamed lines; it does not exhaust deleted/unreachable/private records, untracked files, unmentioned aliases or prior human knowledge. No case is certified untouched, no replacement was read or selected, and no evaluation manifest or implementation was edited.

All88 frozen Sprint10 inputs and every selected historical evidence source remained byte-identical. Of338 checked existing input/context files, four active corpus-planning files changed concurrently after the scan: the corpus-adjudication design, dispute inventory, evidence-adjudication specification and corpus planning draft. Root confirmed these were its authorized CP01 correction after the financial batch release; originals and the correction record are retained under `review/semantic-kernel/corpus-provenance-adjudication/planning/root-findings/`. This audit did not edit them; their exact before/current hashes are recorded as planning-context drift, so the report does not falsely claim all scanned context remained stable. Those changing files supply no selected evidence for the twelve-case conclusions.

The two scripts reconstruct discovery and the explicit assessment from existing files and refuse to overwrite their principal inventories. A future rerun should use a fresh output revision and bind its own repository state; reproducing current working-tree bytes is not assumed. `verification.json` and `artifact-inventory.json` record the final integrity checks and artifact hashes. This work changes only the new audit directory.
