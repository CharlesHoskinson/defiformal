## Purpose

Requires independently expected financial observations, meaningful runtime negatives and exact accepted dependency/review identities before claiming extension results.

## ADDED Requirements

### Requirement: XE01 Independent financial and comparator fixtures

Evidence SHALL contain the twenty planned fixture families with literal complete expected executions and separately expected projections, preserving distinction between real runs and synthetic observer pairs.

#### Scenario: E01 The three-old/three-new-slot funded family is executed

- **WHEN** the three-old/three-new-slot funded family is executed
- **THEN** all20 complete schedules preserve the old7/3/1 transfers with exact histories/refusals and independent full expected worlds.

#### Scenario: E02 Single-field projected observation pairs are compared

- **WHEN** single-field projected observation pairs are compared
- **THEN** each named changed field is detected and an independently constructed equal nonempty control passes.

#### Scenario: E03 A candidate runner or projection computes its own expected value

- **WHEN** a candidate runner or projection computes its own expected value
- **THEN** that result is insufficient as the independent financial oracle.

### Requirement: XE02 Real mutations and inherited controls

Evidence SHALL execute the sixteen specified runtime mutations and every accepted predecessor runner control with exact source bindings, protected positives, complete inventories and preserved blocked attempts.

#### Scenario: E04 A compiled runtime mutant changes the designated semantic behavior

- **WHEN** a compiled runtime mutant changes the designated semantic behavior
- **THEN** its designated comparison is false, all comparisons execute and global protected positives remain true.

#### Scenario: E05 A mutation has a type error, timeout, empty output or a bad failure-count protocol

- **WHEN** a mutation has a type error, timeout, empty output or a bad failure-count protocol
- **THEN** the result is blocked execution rather than detection.

#### Scenario: E06 Predecessor controls are adapted

- **WHEN** predecessor controls are adapted
- **THEN** every original control has an exact source/CLI/protocol mapping; actual counts and newly added controls are measured separately.

### Requirement: XE03 Mandatory accepted API refresh

Official planning freeze SHALL wait for accepted S10/M3/M4 and exact refresh of all proposed APIs, field projections, slots, admission, tree proofs, fixtures, baselines and runner contracts.

#### Scenario: E07 Only the current provisional M3/M4 plans exist

- **WHEN** only the current provisional M3/M4 plans exist
- **THEN** implementation and official planning acceptance remain blocked_missing_accepted_dependencies.

#### Scenario: E08 Accepted predecessor fields or semantics differ

- **WHEN** accepted predecessor fields or semantics differ
- **THEN** the draft is explicitly revised and validated before same-candidate review, preserving old snapshots.

### Requirement: XE04 Complete proof and independent review evidence

Acceptance SHALL enumerate actual proofs/axioms and all scenarios, require same-candidate nonauthor GPT-6/Fable planning and Grok/Fable result reviews, and preserve held source/corpus evidence.

#### Scenario: E09 Proof and integration checks finish

- **WHEN** proof and integration checks finish
- **THEN** full types/premises/provenance classify generic/instance/counterexample/generated declarations with no forbidden proof dependencies.

#### Scenario: E10 A required review or actual execution is unavailable

- **WHEN** a required review or actual execution is unavailable
- **THEN** the attempt and pending status remain visible; planning-file completeness is not implementation acceptance.

#### Scenario: E11 All scoped evidence and required reviews pass

- **WHEN** all scoped evidence and required reviews pass
- **THEN** the exact delivered revision is read back and archived while dynamic provenance, Atomic extension, corpus/evaluation and deployment obligations remain open.
