## Why

The published verification-library milestone has accepted implementation and
engineering replay, while historical effort is unavailable and actual outside
reproduction is absent. A separate validation change gives prospective measurement
and outside usability evidence explicit completion criteria without making release
delivery depend on recovering missing historical data.

**Draft — 2026-11-18, pending owner review.** This plan accompanies the proposed
[delivery amendment](../competitive-landscape-adoption/proposal.md). Neither the
transfer nor any validation result is accepted merely because these files exist.

## What Changes

- Establish a prospective accounting protocol with separate component/shared
  scopes, source identities, line counts, attribution and defined effort units.
- Run one new two-component reuse experiment with separately recorded effort,
  failed attempts and shared overhead. This measures a new experiment; historical
  vault/token0/workflow effort remains unknown.
- Preserve original adoption task I.4 in full: an actual outside developer follows
  the P18 README and records role, outcome and setup time, whether pass or fail.
- Preserve the outside package-only criterion from original adoption III.1: an
  actual outside developer receives the released compiled package and replays it
  using only the package instructions and stated host prerequisites.
- Keep both outside procedures and outcomes distinct, even if one person performs
  both. Record problems honestly and require a new run before claiming a repair
  succeeded. Agent checks and downloads cannot close these tasks.

## Capabilities

### New Capabilities

- `competitive-validation-evidence`: prospective effort records and actual outside
  P18/package-only reproduction with explicit evidence and claim limits.

### Modified Capabilities

None in `openspec/specs/`. The unarchived adoption delta's measurement and outside
requirements are allocated here by the accompanying amendment; it does not add
outside-validation requirements to the delivery milestone's future main spec.

## Impact

Planning and future evidence records only. Existing implementations, proof
statements, releases, frozen reviews and historical accounting remain intact.
No new financial feature, dependency upgrade, historical effort reconstruction,
competitive speed claim or adoption claim is required. Completion of this change
requires actual observations and independent evidence review; approval of the
delivery amendment alone cannot complete it.
