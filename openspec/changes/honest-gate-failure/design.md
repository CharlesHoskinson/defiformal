## Context

`paper/build.sh` is the advertised way to obtain the paper — `README.md` says so,
and the PDF is gitignored, so it is the *only* way. It is also the script that
enforces the project's editorial rules: no undefined references, no stale
artefact, no changelog language in the manuscript. It fails loudly by design, and
its header says why:

> Fails LOUDLY: a silent compile failure once let two whole sections sit
> unrendered while a stale PDF kept being exported.

The lesson learned there was *do not fail silently*. The lesson not learned was
*do not fail inaccurately*. Loud and wrong is worse than silent and wrong,
because it directs effort.

## The taxonomy this change introduces

Every gate outcome is exactly one of three things. The current scripts have
names for one of them.

| Outcome | Meaning | Today | After |
|---|---|---|---|
| **VIOLATED** | The check ran, examined a non-empty corpus, and the property is false | exit ≠ 0 | exit `1` |
| **BLOCKED** | The check could not run — missing input, unreadable path, absent tool | exit ≠ 0, reported as VIOLATED | exit `3` |
| **VACUOUS** | The check ran but examined nothing; the property is trivially true | exit `0`, reported as pass | exit `3` |

The whole defect is that today's callers see only `0` versus non-zero, so
BLOCKED collapses into VIOLATED and VACUOUS collapses into pass. Both
collapses produce a confident false statement, in opposite directions.

`3` is chosen for BLOCKED because `1` and `2` are already in use across the
suite (`gate33_cert_check.py` exits `2` on a missing IR directory today) and
because a shell `||` branch cannot distinguish exit values without extra work —
which is the point. A caller that wants to merge them must say so explicitly.

## Why not simply drop the redirect

Removing `>/dev/null 2>&1` from line 49 fixes the *discarded diagnosis* but not
the *false message*. The `||` branch still fires for both outcomes and still
prints "a headline total disagrees with the verdicts" for an `EACCES`. Both
halves must change together:

```bash
# before
node ../formal/v3/totalgate.mjs >/dev/null 2>&1 || die "a headline total disagrees with the verdicts"

# after
gate_out=$(node ../formal/v3/totalgate.mjs 2>&1); gate_rc=$?
case "$gate_rc" in
  0) ;;
  1) printf '%s\n' "$gate_out" >&2
     die "a headline total disagrees with the verdicts" ;;
  *) printf '%s\n' "$gate_out" >&2
     blocked "totalgate could not run (exit $gate_rc) - the totals were NOT checked" ;;
esac
```

`blocked()` is a second exit helper beside the existing `die()`. It prints in a
different colour and a different word so the two are not confusable in a
terminal scrollback, and it exits `3` so a CI caller can branch.

The distinction is load-bearing for the reader, not just for CI. "The totals
were not checked" sends someone to their environment. "A headline total
disagrees" sends them to `atlas.tex`. Today the script says the second when it
means the first.

## Why `cd` guards are the same bug

`gate.sh:3` is `cd /root/defiformal` with no guard. A failed `cd` in a
non-`set -e` script is a no-op that keeps going. Everything downstream then
measures the wrong tree and reports content verdicts about it — `FAIL 61 of 72`
is generated by a harness that read no corpus at all. That is BLOCKED rendered
as VIOLATED, identical in kind to line 49.

The fix pattern already exists in-tree and is not being invented here:

```bash
cd "$(dirname "$0")/../.." || exit 3     # gate.sh, negtest-*.sh, loop2gate.sh
cd "$(dirname "$0")"      || exit 3      # smoke.sh already does this
```

Script-relative resolution also removes the `/root/defiformal` literal from
thirteen shells as a side effect. That is a welcome consequence, not the goal —
the goal is that a failed `cd` stops the script.

## Why vacuity belongs in this change

A reviewer could reasonably argue vacuity is a separate concern. It is not,
because it is the same sentence with the sign flipped. `verify_final.py` printing
`0 of 0` and exiting `0` is the script asserting "the property holds" about a
corpus it never found — exactly as line 49 asserts "the totals disagree" about a
gate it never ran. Both are statements about evidence that does not exist. Fixing
one and leaving the other would leave the build able to lie in the direction that
is harder to notice, because a green pass invites no investigation.

The guard is small and uniform:

```python
if not files:
    sys.exit(3)     # examined nothing; not a pass
```

## Audit strategy

The repo's standing rule is that a checker never observed failing is not
evidence, and the `negtest-*.sh` family already applies it to the content
checkers with `CAUGHT` / `MISSED` reporting. This change extends that discipline
to the reporters.

The new `negtest-reporting.sh` is a **polarity harness**: for each of the three
outcomes it constructs the condition and asserts the caller says the right
thing. The critical case is the one that would have caught this defect —

- make `totalgate.mjs`'s input unreachable (`chmod 0` on a copy of the expansion
  root, a real `EACCES` from the filesystem rather than an injected throw),
- run `build.sh`,
- assert the output contains "could NOT" and does **not** contain "disagrees".

A fault injected before the real syscall would test the handler rather than the
subject, so the harness uses a genuine permission error on a real path. Each
polarity must be observed in both directions: the blocked case must not print
the disagreement message, and the genuine-disagreement case must still print it.
A harness that only ever sees one polarity has not discriminated anything.

## Risks

- **`set -uo pipefail` and `$?` capture.** `gate_rc=$?` must be on the same line
  as, or immediately after, the assignment — a `local` declaration or an
  intervening command clobbers it. The task list calls this out because it is the
  usual way this refactor silently breaks.
- **Exit `3` may be read as failure by an existing caller.** `gate.sh` runs
  `build.sh` and greps its output rather than its exit code, so it is unaffected;
  any other caller is enumerated in task 4.1 before the change lands.
- **The build still fails after this change** until the root-resolution work
  lands, because `totalgate.mjs` is only one of the paths involved. It will fail
  *honestly*, which is the deliverable. This must be stated in the change's
  completion note so it is not mistaken for an incomplete fix.
