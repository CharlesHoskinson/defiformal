# finite-participant-regression-evidence Specification

## Purpose
Specify finite participant regression evidence for actual finite shared-state execution with explicit assumptions and reproducible evidence.

## Requirements

### Requirement: Independent expected observations and classification

Evidence SHALL cover the nineteen fixed fixture IDs with independently constructed full expected observations, distinguish generic proofs, concrete proofs, funded executions, synthetic comparator pairs and logical counterexamples, and retain every required scenario in an explicit coverage map.

#### Scenario: Oracle independence
- **WHEN** a production result is checked
- **THEN** its expected ledger, store, receipts, outputs, histories, failures and attempts were not computed by the candidate dispatcher or compared executor

#### Scenario: Evidence class separation
- **WHEN** a synthetic pair or false-promises proposition passes its intended check
- **THEN** it is not counted as a funded financial execution or a generic preservation proof

### Requirement: Real executable source mutation

Every planned mutation SHALL change the actual production runtime closure, compile it and make its named independent semantic oracle false while protected positives remain true; blocked or vacuous executions SHALL receive no detection credit.

#### Scenario: Sixteen real faults
- **WHEN** each planned mutation is run as its own one-mutant SPEC invocation on the frozen runtime source, with that mutant's required_false and that mutant's expected_protected_check as that SPEC's positive_checks
- **THEN** each compiles and produces its named false check with nonempty results and protected positives. A single 16-mutant SPEC whose positive_checks unions labels that other mutants must falsify is not production evidence

#### Scenario: Timeout or compiler refusal
- **WHEN** a mutated closure times out, fails compilation or emits no valid nonempty checks
- **THEN** the case is blocked with raw evidence and is not reported as a financial detection

### Requirement: Inherited CLI controls and complete proof inventory

The runner SHALL preserve all final accepted predecessor defensive controls through a literal driver/root/namespace/proof-regex/error/fixture mapping, and verification SHALL inventory actual imported explicit, generated, supplemental and private declarations with full statements and axiom dependencies.

#### Scenario: Predecessor control adaptation
- **WHEN** accepted M2 driver and controls are available
- **THEN** every established control has an exact old/new mapping and actual execution; the actual accepted S10 65-case run retains its source identity and is not relabeled as an M3 run

#### Scenario: Proof-tail and private declarations
- **WHEN** runtime proof stripping and full Lean verification execute
- **THEN** runtime imports exclude proof-only fixtures while full proof inventory includes private names and every imported declaration with source hashes

### Requirement: Dependency and independent acceptance gate

Official planning freeze SHALL require accepted/delivered M2 and refreshed exact dependencies, then independent nonauthor GPT-6 review of the hashed local planning package. The preserved official-r1 Fable 5.1 medium invocation is not a verdict. Implementation acceptance SHALL require actual checks and independent native Grok/Fable5.1 medium reports with exact source, tool, model and evidence identities.

#### Scenario: Pending predecessor or no verdict
- **WHEN** M2 is unaccepted, or a native invocation is unavailable or returns no substantive verdict
- **THEN** the planning gate remains open and no implementation or completed roadmap result is claimed

#### Scenario: Final source-bound evidence
- **WHEN** implementation and tests eventually finish
- **THEN** fresh or explicitly retained equivalent baselines, mutation/control results, full source/proof inventory and independent verdicts bind the actual candidate, with no sorry/custom axiom/native_decide or deployment-fidelity claim
