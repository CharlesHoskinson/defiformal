# Matching claims in LaTeX

**Claim.** A gate that locates a figure by pattern-matching the LaTeX **source**
cannot bound what the reader sees. This is not a bug list to work through; it is
a property of the approach, and ten review rounds establishing it is the main
thing this page exists to save you.

## What was tried, and how each failed

| attempt | defeated by |
|---|---|
| `tex.includes("$1{,}259$")` over the whole document | a needle collision — strip the approx markers, `strict` becomes `45.3`, satisfied by the **coverage** literal eleven lines above. Exit 0, "all headline totals agree", while the paper claims 29.0% |
| Anchor to the claim's `\label` block | a `\label` sits in a table's **caption**, *below* the tabular body. Slicing forward missed `total & --- & 1259 & 570 & 689 & 15` entirely |
| Anchor to the claim **sentence** | `meas:covsens` states both the pooled and the strict figure, so the collision lived *inside* the anchor |
| Require every claim site to agree | the flagship total has **three** sites (lines 217, 1297, 1536); hand enumeration missed one three rounds running |
| Strip comments | LaTeX comment semantics are backslash **parity**: `\%` is literal, `\\%` is a line break plus a **live** comment. A single-preceding-character test kept the decoy |
| Strip `\iffalse ... \fi` | its dual `\iftrue $690$ \else $689$ \fi` typesets 690 while the matcher sees 689 |
| Refuse *any* conditional in a claim region | a conditional **wrapping** the region puts both tokens outside every inspected span; padding puts `\else` outside the window. Defeated by **position**, not form |

Each fix was correct about the shape in front of it. None generalised.

## Why it cannot generalise

Conditionals are not the only gap. A `\newcommand{\x}{... $689$ ...}` that is
never invoked carries the claim phrase in text TeX never typesets, with no
conditional token anywhere. Deciding what TeX typesets requires running TeX.

There is also a figure that cannot be located at all: **`inad` = 15**. The digits
`15` occur **six times** in visible text (lines 957, 1029, 1157, 1536, 1970,
2692) and most are unrelated counts, so the rule that fixed every other figure —
*every site stating this number must agree* — would fail on a **correct** paper.

## Two remedies, both measured feasible

**1. Compare against the typeset output.** `paper/build.sh` already produces
`atlas.pdf` before the gate runs, and `pdftotext` is installed.

Measured: `pdftotext -layout` preserves the total row **as a row** —
`total  —  1259  570  689  15` — so the cell-identity guarantee survives the
move. Four of five claim phrases appear verbatim in the typeset text; the fifth
(`Pooling all`) does not, almost certainly line wrapping or hyphenation, which
is the new failure class this approach would have to shake out.

Closes conditionals of every form and position, uninvoked macro bodies, and
comments at once, because it reads what the reader reads.

**2. Emit the figures from one source.** `\newcommand{\obligationsTotal}{1259}`
generated by the gate, with the prose using the macro. Every figure then has
exactly one definition site by construction, the comparison becomes an identity
rather than a search, and the `inad` problem disappears because the gate never
has to find `15` in prose again.

This is the stronger remedy. A reviewer recommended it in round 12; it was
deferred, and became the binding constraint for the next ten rounds.

## Things that are still true and worth keeping

Whichever remedy is adopted, these were learned the hard way and still apply:

- **Cells carry meaning by position.** Testing that each number occurs
  *somewhere* in the table let `1259 & 689 & 570 & 15` — arithmetically
  impossible — pass every check.
- **A duplicated claim is ambiguous**, not a pass. Two candidates means the gate
  cannot tell which the reader sees.
- **`\iff` is not a conditional.** A naive `\\if[a-zA-Z]*` matches the math
  operator, which this manuscript uses at line 914.

## A live finding

While building this, the gate work surfaced a real arithmetic error in the
paper. `sec:extend` states the residue as 689, then splits it 385 + 301 = **686**
— the *withdrawn* round-2 residue this gate blacklists as stale. Recomputed on
the seven categories the section names: **404 + 285 = 689**. Unfixed; it needs an
authorial decision.
